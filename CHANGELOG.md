## 2026-07-29 (second session) — Phase C: the set sheds its taste

**Egildo: "let's do phase C, we have to reorganize this in the most clean fashion, carve and we'll start working on the spreadsheet again."** The last open task from the surface round, and the one that makes the doctrine true in the code rather than only in the commit messages.

No labels, no glyphs, no keywords, no groups; no labels on the arguments; no labels on the domain members. *Because* only this package can know that a formula lives on a `td` and not a `th`, and only a host can know what to call it, which glyph it wears, or which section it sits in — Egildo's ruling of 2026-07-28 ("split the entry: capability stays, taste moves"), now prosemirror-verbs' V12 as amended. The old wording drew the line at chrome and stopped one layer short: a name is not chrome, but it is not ours either.

**What did not get thrown away.** A bare capability set hands every host a bill for eighteen names and a designed glyph vocabulary, so the taste ships too — separately, as **`spreadsTaste`** (`src/taste.ts`): inert data keyed by id, including the three `table:row-region:*` forms a host's `expand` produces. Two things stayed out of it deliberately — **`group`**, because a category name means nothing except against the host's own list of sections, and **chords**, because the keyboard is the host's court and our keys already travel as the `gridKeys` policy.

**What it cost prosemirror-verbs**, since the shed was only possible if the contract allowed it: `VerbArg.label` and `DomainMember.label` became optional; `expand` now emits bare capabilities for bare members; a field's face falls back from the argument's label to the *verb's* label — which matters, because `args` is a capability key closed to layers, so a label buried in it would have been the one piece of taste no attribute could reach. New stone **V13 — taste is a cascade of layers** (pinned), and V12 amended with the rule that tells the halves apart: *could a second editor reasonably disagree?*

**Verified in the field, not asserted.** The venue's strip came up identical — same glyphs, same order, same eleven controls — with `table:abbr`'s label four claimants deep (`naming` → `spreads (suggested)` → `venue naming`), the venue's own word winning exactly where a host should win. ## 2026-07-29 — The second keystroke: an intention enforced through the wrong seam

**Egildo, typing: "If I type '12' on a cell it puts first '1' and then '2'. Absolutely ghastly."** The cell kept only the second character. It took three dead theories and an instrument to name, and the coach's first two confident diagnoses were both wrong — worth recording, because the pattern is the finding.

**What it was.** ProseMirror was handling every keystroke after the first. `stopEvent` — the *only* place the editor asks whether an event originating inside a node view is its business — answered `!type.startsWith("key")` unconditionally: **keys are yours**, buffer open or not. So the second character reached the editor's own input machinery, which did the correct thing for a `NodeSelection`: replaced the selected node with that character. The cell node was deleted out from under a still-open buffer, `editing` cleared by `mapped.deleted`, and the buffer was orphaned. Every visible symptom sat downstream of one wrong boolean.

**Why it hid for nine days.** The reflection round (2026-07-20) settled the right intention — *"the buffer is stricter, not looser: a native input owns every keystroke, so the buffer stops propagation of all keys"* — and chose the wrong mechanism for it. `stopPropagation` stops DOM listeners; it does not stop ProseMirror. The buffer was stopping propagation faithfully the entire time. **The general form, worth more than the fix: an intention enforced through the wrong seam is not enforced.** Fixed by making `stopEvent` answer honestly — while a buffer is open every key is the box's; idle, they fall through to the courts exactly as the reflection round ruled, so undo inside the grid still works.

**Two dead theories, logged rather than quietly dropped.** *The seeded typing path re-seeds* — killed by driving real keydowns: the buffer survived, no second `startEditing`. *A blur with no new focus owner settles* — real, fixed, **and not the cause**; the symptom was unchanged. That guard stays on its own merits (a blur nobody took is an element hiding or a layout shift, not a user departing, and committing a half-typed value there is wrong whatever else is true), *instead of* being reverted for having been found on a false trail. Its carried cost is named: clicking dead page space no longer commits on the spot.

**The tooling gap that let it ship, stated plainly.** The box has two input seams — `onKeydown` for real typing, `onBeforeInput` for IME, autofill and synthetic input — and **every browser tool available to the coach reaches only the second**, where the code was correct. CDP's `type` fires no keydown; its `key` action does not dispatch digits. So the most-used path into the most-used behaviour was the one no automated check could exercise, and "verified live in the venue" was true and insufficient on the same day. Closed by pinning `stopEvent`'s contract in jsdom, where a browser tool is not needed: buffer open ⇒ keys claimed, idle ⇒ keys released. Both new pins were falsified before being trusted — reverted the fix, watched them fail, restored it.

**Found by instrument, not by argument.** A disposable venue probe recorded every key, focus and input event in capture phase alongside each transaction's meta and steps; the answer was one line — `doc +1 step(s) … (no meta) … ReplaceStep`. Removed once it had done its work. Suite at 154.

## 2026-07-28 — The functions round, and the anatomy finally looks like itself

**Egildo asked for more functions and for styles that make headers, footers and colgroups readable. The function half had a structural obstacle underneath it**: all five v1 functions were aggregates, and `evalCall` flattened every argument into one list, so `ROUND(x, 2)` would have collapsed `x` and `2` together. The language could not round a number, and the reason was shape, not vocabulary. So the kinds got carved before the set grew: an **aggregate** flattens references into its value list, a **scalar** takes one value per argument — which makes `ROUND(a whole column, 2)` an honest `#VALUE!` rather than a silent nonsense. Both now live in a declared table (kind, min/max arity) instead of a switch, so growth is one row plus one case; a name declared without an implementation throws at module load rather than answering `#NAME?` from a cell; and **arity is checked before any argument evaluates**, so `ROUND(1, 2, 3)` is `#VALUE!` *because* a silently ignored tail is how a language drifts, *instead of* the permissive shrug every spreadsheet regrets. The grammar was left alone: `^` was considered and parked, an operator being a grammar round rather than a vocabulary one.

**Fourteen functions now, all inside the v1 fence** (pure, numeric, non-volatile — no conditionals, strings, dates): aggregates gain `COUNTA`, `MEDIAN`, `PRODUCT`; scalars arrive at all with `ROUND`, `TRUNC`, `ABS`, `SQRT`, `POWER`, `MOD`. Four conventions carved where the naive implementation would quietly be wrong, each chosen against the JavaScript default: `ROUND` is half-away-from-zero (`ROUND(-2.5)` = `-3`), not `Math.round`'s half-toward-`+∞`; `MOD` takes the divisor's sign (`MOD(-1, 3)` = `2`), not `%`'s; `SQRT` of a negative is an error, this language having no complex numbers to hand it to; and nothing infinite or `NaN` may reach a cell and pose as a number, so `POWER(0, -1)` is `#VALUE!`. **Empty aggregates answer by whether they have an identity** — the empty sum is `0`, the empty product is `1`, and `AVG`/`MEDIAN` say `#DIV/0!` rather than inventing one. Flagged rather than changed, since it is inherited: `MIN`/`MAX` of nothing still answer `0`, which by that rule should probably be an error too.

**§9's open question closed, and it is a behavior change worth naming loudly.** `COUNT`'s meaning had stood open ("non-empty? numeric?") since the formula round. The answer was that v1's single `COUNT` counted non-empty — it was `COUNTA` wearing `COUNT`'s name, which is precisely why it could not be written down. Naming both members settles it as every spreadsheet already has: over `[1, empty, "x"]`, `COUNT` was `2` and is now `1`, with `COUNTA` answering `2`. The pair is also the sole place text is tolerated inside an aggregate, and the exception earns itself — counting is the one operation for which text is data rather than a category error. The test that pinned the old meaning failed exactly as it should have, and was rewritten to pin the pair.

**The anatomy was in the document all along and had never been dressed.** The base theme now reads the regions it already had: a firm rule closing the header band, the accounting double rule above the footer's totals, the row-header column taking that band rule turned on its side, the caption seated above the grid as the table's name. The one that is more than dressing is `tbody + tbody`, which **finally draws the partition** — until this rule, splitting a body changed the document's grouping and nothing on the screen, so a verb built a week ago was invisible to the person using it. Not one line applies a class: this is "structure selects itself" collecting its dividend, and a serialized table dropped into any page with this sheet reads identically. Every knob rides a custom property; row striping ships **off** behind `--spreads-row-stripe`, *because* a stripe is a taste and not a structure.

**The colgroup answer was measured rather than assumed.** CSS grants column boxes four properties, and their borders lose every tie to the cell's own under `border-collapse` — so a group boundary must out-weigh the grid line to exist, which is why the rule is wider rather than merely darker. Probed live: a 6px colgroup border grew a test table from 83px to 88px, so it wins the collapse and renders. The ceiling is carved with the feature — a colgroup cannot tint text, align it, or carry any other readability affordance, and per-column styling beyond those four properties belongs to the typed-column layer, not here. Noted honestly: our colgroups are created for widths and there is exactly one, so the rule serves pasted and hand-authored tables today.

Pressed in the field: the venue's demo table became a real anatomy — caption, thead, two tbodies, a two-row tfoot, a `scope="row"` column — and reads correctly, with `=SUM(Prezzo)` at 59 across both bodies (the spanning ruling holding) and `=ROUND(AVG(Prezzo), 2)` at 19.67, a scalar wrapping an aggregate. Suite at 151, typecheck clean, console clean.
