# The Architecture — second edition

Design decisions descending from [the Tablet](tablet.md). Two layers: **the consequential choices** — the spine, each naming its parent principles — and the **working sections**, organized along the seam map and structured as the complete implementation description even where content is still stub. Marks: settled / pinned / open, per the Tablet; depth annotations (circled / ratified on briefing / proposed, unruled / settled as direction / interim law) record how deep the round was and what would move it. Battlegrounds 1 and 2 have pressed parts of this into code — items say so where it happened; the battle stories live in the changelog.

**The seam map.** Four seams, declared so no round welds across one: **the factory** (schema, §1), **the core** (engine, state, commands, interaction, node views, §2–§6), **the chrome** (presentation, rulers, icons, §7), **the frontier** (names, formula language, evaluation, §8–§10), plus **the borders** (serialization, collaboration, testing, §11–§13). The classic failure the map guards against: the core quietly importing the evaluator. Whether the seams become separately installable plugins is C15's open round.

## The consequential choices

Condensed from the circled rounds of 2026-07-14/15; the layer's ordering and C2, C5, C11 (and the Tablet's P4) are ratified on briefing — direction, not gospel. The parentage rule is self-auditing: a choice that cannot name its parents is either unjustified or reveals a missing principle (it found P4).

- **C1 — The document is the sole truth; ProseMirror is the transactional store** (P1) · settled — Everything the table *is* lives in the doc; everything ephemeral — buffers, hovers, drags, selections — lives in the view layer and dies there. Inside tables, ProseMirror is our document engine, not our text editor: cells are atoms with node-view surfaces. The named bet, accepted.
- **C2 — The anatomy is structural** (P2) · settled, ratified on briefing — `thead`, `tbody`, `tfoot`, `caption` are node types, not serialization garnish. Boundaries have editing meaning: moving a row into thead is a promotion, not a reorder.
- **C3 — Every fact sits in its register's seat** (P3) · settled — Value in element content, automation in attributes, presentation in constructed stylesheets. `<td data-formula="=SUM(Price)">42</td>`; standing cells pristine; the stylesheet is the only presentation channel.
- **C4 — Names come from the content** (P2, P3) · pinned — Scope'd headers name columns and rows; formulas and slices speak those names; automation borrows names the content earned, never invents its own. No positional notation exists above the engine room. Test: `=SUM(Price)` resolvable from standard, valid markup alone.
- **C5 — Positions live below deck** (corollary of C4) · settled — Geometry machinery is internal; positions never appear in notation, document, or the user's vocabulary. The resolver translates gestures (positions) into sentences (names).
- **C6 — Two modes, one seam** (P4, C1) · pinned — Grid mode: cells as units, custom selection, the cross cursor. Edit mode: one cell's buffer. Commit is the seam, doing three jobs — mode boundary, evaluation trigger, undo grouping.
- **C7 — The gesture law** (P4; generalizes C6) · pinned — Everything continuous streams in the ephemeral layer; state changes atomically at seams. Cell edits settle as one transaction; drags stream and settle at pointerup; the pointer's purpose is computed state, the cursor its costume.
- **C8 — Enforcement is declaration-keeping, with two duties** (P3, P5) · settled; second duty from the incumbent survey, 2026-07-15 — The engine makes the document true in both registers: it keeps the **shape legal** (structural normalization of ragged rows, colliding spans, paste and collab wreckage; the incumbent's `fixTables` proves the duty and the seat) and it keeps the **declarations true** (on settle: dirty-mark, evaluate topologically over the name graph, one dispatch — synchronous, bounded, no volatiles, cycles are errors). Both duties seat in `appendTransaction`; the cascade rides the settle (Egildo's economy ruling).
- **C9 — Errors are values** (P2, C8) · settled — Failure occupies the cell, propagates through dependents, and serializes: the markup admits what broke. Two validation species kept apart: resolution errors (automation failing) and data validation (content violating declared expectations).
- **C10 — Collab bends, doctrine doesn't** (C8) · settled as ruling — Cell-wise atomicity is accepted over collaborative perfection; the mitigation — recompute rides the originating transaction — stays pinned until proven.
- **C11 — Semantics are rewarded, never gated** (P2, P5, P6) · settled (2026-07-15, circled; supersedes the "no names, no formulas" form, whose cliff contradicted C14's own guard) — An anonymous table is a fine table with every capability's bottom step: scaffolding formulas (C16) work from day zero. What names buy is durability and meaning — references that survive every edit, markup that says what it computes. The fat ruler and fragile positional refs are the face of an unnamed table, and the interface actively offers the upgrade. Semantics pay; they never gatekeep.
- **C12 — Everything is a command** (P1) · settled (Egildo) — Every mutation is a ProseMirror command: composable, keybindable, dry-runnable (call without dispatch — menu enabling for free), testable headless. UI never mutates; it invokes. The command vocabulary is the plugin's verb list and the manual's future words.
- **C13 — The view is downstream** (C1, C12) · settled (Egildo) — command → transaction → doc → derived indexes → node views. Node views are renderers and input surfaces, never truth-holders; their ephemeral state becomes real only by dispatching through the front door. A node view that makes decisions is a smell.
- **C14 — The spec is the contract: ceiling, never floor** (P2, C2, C4) · settled (Egildo) — The full HTML table model is in scope: `caption`, `colgroup`/`col`, `thead`, multiple `tbody` row groups, `tfoot`, all four `scope` values, `headers` overrides; the resolver implements the spec's header-association algorithm, so formulas and assistive tech read the same table by construction. **Supported is never required** (Egildo's guard): the bare-tbody table is first-class; capability grows monotonically with markup — never a cliff. Survey duty discharged (battleground 2; spec text read): "applies to some of the **subsequent** cells" — headers name only what follows them, and scope=col crosses row groups into tfoot, confirming §8's accessibility/name split. Test: every command except formula-entry applies to a table with zero named columns and rows.
- **C15 — The seams may become packages** (C11, C14; incumbent survey) · proposed, unruled — The incumbent survived a decade as a family (core plugin + optional plugins + schema factory), not a monolith. Our capability gradient suggests the same shape: factory + core + chrome + frontier — plus the scaffolding adapter (C16's training wheels) — as separately installable capabilities, making C11 true at the package level. Nothing settled binds across a seam yet; its own round before anything does.
- **C16 — Queries in the kernel, coordinates on the ring** (C4, C5, P6) · settled (2026-07-15, circled) — Kernel references are semantic queries: a name resolves the way a selector does, through the association algorithm — no selector could ever match `A1:B1`, because a coordinate describes grid geometry, not the document. Positional notation never enters the kernel: a **boundary adapter** owns its whole lifecycle — parse the coordinate token, resolve via the grid map, adjust through structural edits (ProseMirror's transaction mapping does the heavy lifting), upgrade to a name the moment one exists (the rename machinery). The scaffolding tier of P6, never a co-equal second system — Excel's permanent-two-notations wart is the refused road. Candidate separate package under C15. Purity test: delete the adapter and every named formula still works; the evaluator's source contains no coordinate code.
- **C17 — The table is a black box to the editor view** (P1, P4, C1, C13) · settled (capriccio, 2026-07-18, Egildo; confirmed by battleground 3 and merged on his ruling, 2026-07-19; source read: the PM guide — without `contentDOM`, "the content becomes a black box to the editor") — One table-level node view owns the entire grid DOM; inside it, no contenteditable: native inputs, roving tabindex, the ARIA grid pattern. P1 is untouched state-side — document, commands, transactions all stay; only the renderer changes hands. Rows and cells re-render through a keyed-by-node-identity diff, so the named bet's buffers survive; what's discarded is ProseMirror's skeleton sync — where both battleground-1 dragon families lived. The boundary shrinks from N cells to one door, killing at the root: DOM-reader mangling, selection leakage, keymap-ordering fragility, and the focus dance's cause. The CellSelection machinery never gets built — grid selection becomes view and plugin state. Accepted costs: third-party decorations don't render inside tables (mitigated — presence is cell-grained by doctrine, §12; the Custom Highlight glimpse covers range painting), paste is self-hosted (C8 wanted it), the scalar-cell commitment hardens (§1). Pinned tests: buffer survives remote redraw under our diff; the a11y tree reads as a grid; emission byte-identical; plugins outside tables unaffected. **Battleground 3 fought and won (2026-07-19): all four pins pressed and held** — in the playground and through the arena's built package (the manual's 42, cascade, one-step undo). Two findings carved in the fight: inner decorations of a contentDOM-less view are ignored entirely, so the update trigger rides the table's *outer* decoration (a state-signature attribute); and the box is its own stopEvent — buffer-consumed keys must stop propagating or they re-enter the grid's bindings. Standing margins: real IME awaits human hands (the arena is always open), caption is render-only.

## The factory

### 1 · Document schema

What a table *is* in the ProseMirror document.

- **The node set** · settled (C2, C14) — `caption`, `colgroup`/`col`, `thead`, `tbody` (repeatable — row groups are real structure), `tfoot`, rows, `td`/`th`. Content expressions make everything beyond `tbody+` optional — `caption? colgroup* thead? tbody+ tfoot?` — so the bare-tbody table is first-class (C14's floor).
- **The schema is a factory; the names are contract** · pinned; names ruled settled (audit round, 2026-07-17, Egildo) — Node specs are generated by a function (the incumbent's `tableNodes(options)` posture) and plugin code locates types by role, never by dispatching on names. The names themselves are package contract, appended as-is — not parameters: the `nodeViews` prop is name-keyed by nature, and the incumbent's decade proves fixed names suffice. Roles remain internal discipline and a discoverability hook. Deliberate consequence: our names collide with prosemirror-tables' — one table system per schema, the seat is taken. Marked door if coexistence ever gets real: `spreads({schema})` resolving node-view keys by role.
- **Computed-cell serialization** · settled as shape, open in detail — `<td data-formula="=SUM(Price)">42</td>`; standing cells pristine, zero plugin fingerprints. Open: the attribute's name (one `data-formula`, or a family as P5 grows), and the parked `<output for>` glimpse (§8).
- **Typed-cell anatomy and emission** · settled (2026-07-16, circled; sources read: MDN and WHATWG on `data`/`time`) — The model stays scalar: raw value, type, and format are cell-node attrs. Emission wraps — `<time datetime>` for temporal values (MDN: must), `<data value>` for the rest; the spec's canonical `data` example is literally our use case. `td` contributes the WHERE, the wrapper the WHAT — two axes, no pleonasm. Parse accepts wrappers and flat `data-*` alike. Untyped standing cells stay pristine text — P6's zero tax. Test: a typed table round-trips without losing value, type, or format.
- **Cell content: scalar vs inline markup** · open, hardened by C17 — Settle-on-commit (§5) pins to scalar cells; the emission wrappers are toDOM's business, so the pin stands. P2's beautiful `<td>` sometimes carries a link, `<code>`, `<abbr>`; the day a cell legitimately needs inline markup, the design comes back up rather than getting a workaround — and under the black box that day costs more (render inline markup ourselves, or the nested-mini-editor pattern). The door stays marked, heavier.
- **`col` carries the column's width** · settled (UX round, 2026-07-20) — `table_col` gains a `width` attr (CSS pixels, or null), parsed from `<col style="width:…">` — the legacy `width` attribute accepted on parse too (C14's ceiling posture) — and serialized as the style form. The ownership ruling and the fixed-layout consequence live in §7.
- **Rows are mixed** · settled (scope round, 2026-07-16) — A `scope="row"` th lives inside tbody rows: content expressions allow header cells in body rows. Open with it: multiple row-header cells per row (legal HTML) — v1 caps at one until the groups round.
- **No formulas on th** · settled (v1 constraint, scope round) — A computed *name* would make the range's identity depend on other cells' values — a self-describing graph. Parked hard until something real demands it; th cells are standing values.
- **Merged cells** · open, instinct recorded — v1 forbids merged data cells; spanning headers (`scope="colgroup"`/`"rowgroup"`) wait for their own round.
- **Residue** · open — Exact content expressions; span constraints (one grouping level each way; no spans across row-group boundaries — the spec forbids the nastiest geometry); `caption` details.

## The core

### 2 · The engine room — derived indexes

No stored model, ever (C1 descended): the node tree is the structure; the engine room holds indexes — derived, disposable, rebuilt on demand. A stored cell-object model would recreate the two-truths problem inside the plugin.

- **The grid map** · pinned; first form built (battleground 2) — A flat width × height slot array holding each covering cell's position; spanning cells occupy multiple slots; every 2D question becomes index arithmetic. The incumbent's `TableMap` shape, stolen whole, **problems array** included (the map diagnoses structural illegality as a by-product of the geometry pass, feeding C8). The built form adds per-row region metadata — the data boundary is a region question (§8) — and reports ragged rows. v1 schema mints no spans, so the span machinery is unbuilt and the pin's spanning-cells test still waits.
- **Memoized by node identity** · pinned — Persistent nodes make an unchanged table the same object across doc versions; indexes cache in a WeakMap keyed by the table node (the incumbent's exact mechanism, verified in source). No invalidation logic; every historical doc version gets its correct map, so undo/redo/collab work for free. Rebuild is O(cells); incremental maps are a deferred optimization with a known shape.
- **The name table and dependency graph** · pinned; first form built (battleground 2) — Names → cell sets (from scope'd headers via the association algorithm, C14); formula cells → name nodes; group names contain member-name nodes (§10). Derived and memoized the same way. Built form: abbr wins, bare identifiers only, tbody-filtered, "subsequent" honored; duplicates mark both entries ambiguous and referencing one is a resolution error (v1 provisional, naming-round cargo). The graph is *implicit* — memoized descent discovers dependencies; explicit edges arrive when incremental recompute demands them.
- **Structural operations are document surgery** · settled — Insert row/column: a transaction inserting nodes; references survive by C4 (range membership grows — no formula rewrites). Promotion into thead/tfoot: move the `tr` across the boundary, retype `td ↔ th` with scope, one transaction. Indexes never participate; they rebuild after. The hard consequences are semantic (names minted or orphaned) — seated in the naming round (§8).

### 3 · Plugin state & enforcement

What the plugin's own state holds — and refuses to hold (derivables belong to §2; ephemera to the view layer).

- **Formula as attribute, value as content** · settled (2026-07-14, circled) — The formula is automation (P3) in an attribute; the `<td>` contains the computed value as real content — readers, scrapers, screen readers get `42`, the attribute is provenance. Supersedes the coach's decoration-based cut (serialized output would have shown formulas where readers wanted data). Rhyme as evidence: XLSX stores formula plus cached value for the same reasons.
- **Format is a declaration** · settled (2026-07-16, circled) — A formula declares how a cell's *value* derives; a format declares how its *text* derives from the value: `content = format(value, spec, lang)`, enforced in the same dispatch, by the same engine, as formulas. Full cell anatomy: raw value in an attribute (machine's truth), formatted text in content (reader's truth), declarations explaining both. The evaluator computes on raw values only, never display text. Formatting is `Intl`'s job under inherited `lang` — deterministic, no viewer-dependent content. Open: the format-spec notation (christening cargo, §7) and the no-`lang` default.
- **Enforcement seats in `appendTransaction`, both duties** · pinned (C8, formulas and formats alike) — Shape kept legal (the fixTables analog, ours harder — "legal" includes regions) and declarations kept true (recompute and reformat in the same dispatch). Test: after any single user action, no observable editor state shows an illegal table or a formula cell disagreeing with its inputs.
- **Selection legality is part of the shape duty** · settled (battleground 1) — A caret inside an atom cell must be unrepresentable: ProseMirror's DOM reader parses node-view-owned cell DOM it cannot understand, and the table mangles (observed twice; story in the changelog). Both entrances guarded: `createSelectionBetween` coerces view-derived selections, `appendTransaction` coerces state-level ones (undo/redo arrive there) to the cell's node selection — the enforcement engine's first working piece, in C8's seat.
- **Stale-value rule** · pinned; implemented (battleground 2) — A cold-parsed value disagreeing with its formula loses; the value is cache. Seated in the plugin view's mount pass (one enforcement run, outside history — undo must not restore staleness); headless, the first dispatch does the same job. Test: a stale fixture recomputes without touching anything else.
- **The state model: cell-wise atomic updates with cascade** · settled (2026-07-15, Egildo's ruling) — The unit of state change is the settle: one cell's atomic update plus automation side effects, one dispatch. Collab complications accepted as known cost (§12).
- **To verify — nothing may lean on these yet** · open, two of three verified (battleground 2) — (a) **verified**: a settle with its appended cascade undoes as one event, demote included (`newGroupDelay` caveat stands: temporally adjacent transactions group — standard editor behavior); (b) **verified**: transitive chains and cycle detection, self-reference included; (c) paste into a computed cell — still open.
- **The mode field's first form** · settled (battleground 1) — Plugin state holds the edit seam and nothing else: `editing: {pos, seed} | null`, the position mapped through every transaction, dying with a deleted cell; `seed` carries type-to-replace's first keystroke. Commands move it via metas; the settle clears it in the same transaction as the content change.
- **Stub** — grid-selection state, dirty bookkeeping: seated when the selection round and the frontier land.

### 4 · Commands — the verb list

Every mutation is a command (C12); this list is the plugin's public verbs. Sketch, unbaptized — names await the christening round:

- Structure: add/delete row and column (before/after) — **built** (2026-07-27, provisional names; rules below). Move row/column: still sketch.
- Regions: promote row to thead / demote; promote to tfoot; make a column the row headers.
- Cells: settle (the one seam); demote formula cell to standing value; fill (copy / series / formula, §5); merge/split (deferred with §1's merged-cells question).
- Selection & navigation: select row / column / table; arrow-walk in grid mode; enter/leave edit mode.
- **Public verbs are selection-driven; seam forms take positions** · settled (audit finding 4, 2026-07-18) — Commands a menu or keymap invokes read their target from the selection (`editSelectedCell`, `selectRelativeCell`, `clearSelectedCells`) and dry-run for enabling — C12's promise made real; position-parameterized forms (`startEditing(pos, seed)`, `settleCell(pos, text)`) are the node-view seam's documented internals — the buffer knows its position and its text. Names remain christening cargo.
- **The verb set is declared data — prosemirror-verbs adopted** · settled (UX round, 2026-07-20, Egildo's ruling) — spreads exports `spreadsVerbs(schema)`: plain entries in prosemirror-verbs' structural contract (id, label, command, faces, chords) — zero dependency, not even a type import owed, because the contract is structural; the audit-round split turned out to be the verbs-shaped cut (selection-driven verbs enter, seam forms stay internal). `gridKeys` doubles as the exported policy layer a verbs host seats before its base keymap (`{ name: 'grid', bindings: gridKeys }`). The split stated so it never blurs: verbs governs the keyboard *outside* the black box — chords, the backstop path, the audit's sight; the box routes its own keys, and no keymap, verbs' included, sees inside it. What adoption buys: hosts build insert buttons, palettes, one day the formula bar (a verb whose readback is the formula you stand on — link's href rhyme) from declarations alone; chrome stays the host's; spreads becomes verbs' first foreign specimen.
- **The structure family is built** · rules ratified on briefing (venue session, 2026-07-27 — direction, not gospel; names remain christening cargo) — Six selection-driven commands in `structure.ts`: `addRowBefore/After`, `addColumnBefore/After`, `deleteRow`, `deleteColumn`, resolving through the selected cell's grid coordinates and refusing honestly: outside a cell selection, on a whole-table selection (it carries no row/column target — guessing one is the magic the dry-run contract forbids), and while an edit buffer is open (surgery under a live buffer would restructure the very cell being edited; settling is one blur away). The carved rules: **R1** a new row joins the reference row's section — after the last thead row is still the thead; crossing the boundary is the regions family's promotion. **R2** a new row is full grid width, copying the reference row's shape per column (a body row beside a scope="row" column keeps the column columnar); ragged holes fall back to the region default. **R3** deleting a section's last row deletes the section (the headerless table is first-class, C14's floor) — except the only body, which refuses: delete-table lives on the Escape ladder, never as a row verb's side effect. **C1** a new column arrives as data — th scope="col" under thead, td everywhere else, even beside a row-header column (one row-header per row is the v1 cap; "make this column the row headers" stays the regions family's verb). **C2** ragged rows clamp — inserts append at a short row's own end, deletes touch only rows that reach the column, a row whose only cell dies goes with its row; repair stays C8's duty, never a side effect. Selection lands on the new material (inserts) or the same coordinates clamped with the walk-left fallback (deletes); one transaction, one undo step, the recompute riding the dispatch — deleting a named column leaves its referents reading #NAME?, the design telling the truth.
- **The verb set grew its first arg-verbs** · built (venue session, 2026-07-27; ratified on briefing; ids and glyphs provisional) — The set is eleven: the structure six with provisional glyphs; `table:insert` now collects rows × cols (a collecting host prompts, blank falls back to 3×3); `table:select` names the Escape rung with a boolean readback; and `table:formula` — the formula bar's seed, its readback the formula you stand on (the promised href rhyme, now real), prefilling the collector and writing through the new public `writeSelectedCell(text)`: the settle seam's selection-driven form, `editSelectedCell`'s symmetry, inheriting the seam's law (leading "=" declares on data cells, plain text demotes). The locally-declared entry contract widened with `args` and `enabled` — still zero dependency on the registry.
- **Stub** — signatures, applicability rules: after the schema residue round.

### 5 · Interaction layer

Spreadsheet-grade editing (P4) — modes, gestures, selection.

- **Settle-on-commit** · pinned (2026-07-14) — Cell edits settle as single transactions at commit (Enter / Tab / focus leaving); mid-edit text is node-view-owned UI state — "like somebody pasted a few chars". The buffer shows the formula for formula cells, the lexical value for standing cells; the grid shows formatted content. Settle parses input by type and locale; what refuses to parse is caught at the seam — validation with teeth, never silent corruption. What it buys, named because argued: native IME, cell-granular collaboration, one undo event per settle, the death of cross-cell text selection. Pinned to scalar cells (§1). Probe finding (battleground 1): the interception seam is `beforeinput`, not keydown — IME and keydown-less input otherwise fall through to ProseMirror's node replacement, which splits the table; type-to-replace seeds the buffer from both entrances.
- **Grid and edit modes** · pinned — Grid mode: cells as units, arrow keys walk cells. Edit mode: caret inside one cell's buffer. Commit is the seam (C6).
- **The navigation vocabulary is the spreadsheet's** · settled (UX round, 2026-07-20; opened by Egildo's hands in the arena) — The first hands-on found the grid unimpressive, and the diagnosis held: movement predated the grid map and stayed 1-D (two arrows, document order; the settle advanced sideways). Ruled: the four arrows walk the grid two-dimensionally on the grid map, clamping at edges, never wrapping (ragged rows clamp to the nearest existing cell in the target row); Tab/Shift-Tab walk document order and wrap at row ends; Enter and F2 open the edit (Sheets' convention); the settle advances directionally — Enter lands the value and moves *down*, Shift-Enter up, Tab right, Shift-Tab left. Excel's directions under Sheets' Enter is exactly what Sheets itself does — coherent, not hybrid. Feel is the acceptance test, and its instrument is hands, not pins. Reflection-round additions (2026-07-20): Shift-Enter and F2 also open the edit; Home/End walk to the row's edges; the *vertical* boundary exits into the surrounding prose (ArrowUp above the top row lands before the table, ArrowDown below the last lands after — the document half of the contract); horizontal arrows clamp always (Tab, Home, End are the horizontal instruments), and Tab at the very last cell falls through to the browser — the grid's honest keyboard exit for focus.
- **The purpose model** · pinned (2026-07-15) — Nobody sets a cursor: the plugin computes the pointer's purpose — what a pointerdown would mean here — as a pure function `(mode, zone, modifiers) → purpose`, testable headless. Zones from hit-testing against the map. The cursor is the purpose's costume: `data-purpose` on the wrapper, mapped in the constructed stylesheet (`cursor: cell`, `col-resize`, `row-resize`). Purpose changes only on zone transitions; hover is ephemeral. Open fork: view-local variable vs plugin-state mirror — probe territory; the incumbent chose plugin-state via metas.
- **The gesture law** · pinned (2026-07-15) — Continuous in the ephemeral layer, atomic at the seam: `setPointerCapture` owns drags, feedback streams without transactions (resize streams into the sheet via `replaceSync`), one settle at pointerup. The incumbent's resize independently converged on preview-then-settle — spending per-move meta transactions where we spend none.
- **The rulers — scaffolding that recedes** · pinned (2026-07-15, Egildo's design) — A fresh table wears classic rulers: A B C / 1 2 3, wrapper-owned overlay chrome, sticky, never document content. Labels are **wayfinding first, scaffolding second**: with the C16 adapter they become speakable coordinates at the bottom step, upgraded away at naming — no coordinate is kernel material, and none survives a naming. When a thead arrives, th cells inherit the identity duties and the ruler minimises to the mechanical strip (drag, resize grips, context menu, add/delete). Recede is per-column — a letter returns for any empty th; scaffolding is exactly as big as what's still unnamed. The fat ruler carries the promotion affordance: using it is what minimises it. Rows symmetric via `scope="row"`, and may honestly never minimise; an inserted row wears its number until named. Header editing keeps the grid grammar: click selects, Enter/double-click dives.
- **The fill handle** · pinned (2026-07-15, no-dependency verdict) — The lil square: a wrapper-owned overlay at the selection's corner, one purpose-zone (`fill` → native `cursor: crosshair`), gesture-law drag (axis-dominance is pure geometry, preview streams, zero transactions), one `fill` command at pointerup. Under semantic references, **filling a formula is literal copying** — Excel's relative-reference rewriting doesn't exist here (C4's kill); a this-row reference (§8) copies unchanged. Fill-to-column-bottom is the on-ramp offering "make this the column's rule" (`col data-formula`, §8) — the gesture teaching the declaration, chrome dissolving into semantics (P6). Series scope · open: v1 instinct is copy plus linear numeric; dates and weekday lists drag in localization, parked. Touch targets belong to the UX campaign.
- **Selection model** · stub, road changed by C17 — Grid selection is view and plugin state, never a custom Selection class: the incumbent's `CellSelection` was the pattern to adopt under the old skeleton; the black-box ruling closes that road — its jobs (rectangles, drawing, remapping) become the table view's and the plugin state's. Headers double as selection gutters; the resolver translates rectangles into names during formula-building. Mid-drag remote transactions must still remap the drag's anchor (thread to §12). Waits on the semantic-selection UX campaign.
- **The keymap-ordering contract** · interim law, mostly dissolved by C17's merge (2026-07-19) — Inside the box, keys never reach keymaps: the dissolution the law named has arrived. Its residual truth: the PM-level backstop path (focus on the editor root while a cell is node-selected) still routes through plugin order, so `spreads()`-before-keymaps remains the documented setup and the suite keeps pinning both sides of the old premise (a preceding `baseKeymap` still deletes a selected cell on that path).
- **Grid keys are a rebindable vocabulary** · settled (audit finding 3, 2026-07-18; story refined twice on 2026-07-20) — Bindings ship as an exported map (`gridKeys`) that `spreads()` installs by default; `keys: false` uninstalls, a custom map replaces. The UX round briefly retired the "bind through your own keymap" promise (the box swallowed everything); the reflection round's courts ruling restored it honestly: under `keys: false` the box claims only intrinsic input and every named key falls through, so an external `keymap(gridKeys)` works everywhere — while with bindings installed, claimed keys are consumed inside the box before any keymap sees them (the `keys` option stays the first-class rebinding path). Intrinsic input never moves: type-to-replace, the beforeinput interception, and the modified-delete guard protect the document's shape and are not bindings. Pinned by consumer-posture tests: default, uninstalled, rebound, replaced.
- **The box claims its vocabulary; unclaimed keys belong to the editor's courts** · settled (reflection round, 2026-07-20) — The audit found the black box swallowing every key it didn't bind: undo was dead inside the grid, and no key could ever leave the table. Ruled: `stopEvent` passes key events through; the box consumes what it claims (preventDefault + stopPropagation), and everything unclaimed bubbles to the editor's keymaps — chords work inside the grid (undo, and any host binding, whatever it is), and the verbs stack the audit displays is now true inside the table too. Three guard rails keep the fall-through safe: **the clamp law** (unclaimed arrows are consumed — the editor's document-order defaults would wrap or drift, and battleground observation showed `Selection.near` bending an ArrowUp into the *previous* cell); **shape protection** (a *modified* Backspace/Delete — Mod-Backspace and friends — over a selected cell clears content instead of reaching a foreign `deleteSelection`, which would remove the cell node; unmodified variants stay the rebindable vocabulary's business; mirrored on the backstop path); and **the buffer is stricter, not looser** — a native input owns every keystroke (its caret, its native undo), so the buffer stops propagation of all keys. C17's battleground-3 finding refines to its accurate form: the box is its own stopEvent *for what it consumes*. Known residue, carved honestly: macBaseKeymap's emacs deletions (Ctrl-h, Ctrl-d) ride ordinary letter keys and cannot be distinguished from host chords — they can still delete a cell node on the fall-through path, exactly as they always could on the backstop path; the durable fix is C8's shape repair, not key blacklists.
- **The Escape ladder** · settled (reflection round, 2026-07-20) — Escape in grid mode selects the enclosing table, and a table selection belongs wholly to the editor: typing replaces it, Backspace deletes it, arrows leave it — keyboard users gain select-table and delete-table for free, and the ladder is the second keyboard exit (cell → table → prose). Escape in a buffer abandons the edit, as always; Escape mid-resize aborts the drag.
- **Entry mode and edit mode are different buffers** · settled (reflection round, 2026-07-20; Excel's own distinction, imported whole) — A buffer opened by typing (seeded) is *entry mode*: the four bare arrows settle it and move in their direction — the rapid-entry cadence (type, ArrowDown, type). A buffer opened deliberately (Enter, Shift-Enter, F2, double-click) is *edit mode*: arrows stay native, moving the caret. The seed already carried the distinction in state; the behavior now honors it. Carved with it, two settles-and-selection repairs from the same audit: the settle's focus follows the *new* selection (the old cell was stealing focus back after every advance — masked by delegation, wrong to a screen reader), and a settle without an advance leaves the selection where the user put it (a blur-settle no longer yanks selection back to the edited cell mid-click).
- **Value XOR formula** · open (Egildo's mark: "we'll see") — A cell is a standing value or a formula, never both. Battleground 2 implements the manual's trial behavior ("=" makes a formula; plain text demotes; buffer shows formula, grid shows value). Working code is not a ruling; the mark stays open until Egildo closes it.
- **Semantic-selection UX campaign** · open — The model is sound (selection = gesture in positions; reference = sentence in names); the gestures are unproven; a mixed UI approach expected (Egildo). Its own playground campaign.

### 6 · Node views

The custom editing surface — the only region not testable headless.

- **The named bet** · pinned; first probe passed (battleground 1) — Cells as atoms with node-view-owned buffers: ProseMirror as transactional store, not text editor, inside tables. The dragon — the focus dance, and buffers surviving redraws mid-edit — was pressed and the bet held: buffers survived neighbor changes and position-shifting changes, focus never blinked (microtask-deferred grab after ProseMirror's DOM sync; settle/cancel refocus the grid). The pin stays until real IME and real collab press it. Under C17 (merged 2026-07-19), cells ARE internal renderer components of the one table view; the buffer doctrine carried whole through both renderers, and the focus dance is gone — outside contenteditable, focus needs no dance (battleground 3 confirmed: direct synchronous focus, no microtask).
- **Thinness discipline** · settled (C13) — Node views render consequences and host inputs; all intelligence lives in plugin state and pure functions.
- **The cell component's anatomy** · settled (battleground 1; re-seated inside the box, battleground 3) — A bare `td`/`th` whose text the component renders itself; edit mode hosts a native `<input>` — IME, spellcheck, autocorrect belong to the platform. Edit mode and selection read from plugin state, triggered by the table's outer state-signature decoration; the box's `stopEvent` claims everything inside, and the buffer stops propagation on its consumed keys (the box is its own stopEvent). Enter/Shift-Enter/Tab/Shift-Tab settle directionally (down/up/next/prev, §5) and Escape abandons — all on the buffer; blur settles in place — a click elsewhere commits, like every spreadsheet. Cells wear the vocabulary (`data-selected`, `data-editing`) and the roving tabindex.
- **Resize is box furniture** · settled (UX round, 2026-07-20) — The C17 dividend collected: no grip elements, no decoration plumbing — the box hit-tests its own column edges (the purpose model in miniature: a pointer near a boundary wears `col-resize`), captures the drag, streams the preview as inline styles ProseMirror never sees (`ignoreMutation` by design), and settles one `setColumnWidth` transaction at pointerup — the gesture law verbatim (C7).
- **Stub** — the overlay layer, the adopted sheet handle on the wrapper, richer `update()` contracts. Filled as the chrome rounds land.

## The chrome

### 7 · Presentation layer

The one channel (C3): a constructed stylesheet, and the vocabulary it selects on.

- **Constructed stylesheets as the one presentation channel** · pinned — A `CSSStyleSheet` owned by the plugin view, `replaceSync` on update, adopted by the document. Unchanged by C17: the black box changes who writes the DOM, not how it dresses. Test: emitted markup contains zero presentational attributes, styles, or classes — one ruled exception, the column width seat (below) — and the table still renders styled.
- **Chrome lives inside the box** · noted under C17 — At the destination, rulers, overlays, the fill handle, and the conjured colgroup are plain DOM inside the table view's subtree: no decoration plumbing, no wrapper tricks. The stage-makeup distinction does the same work it always did.
- **The stage-makeup distinction** · settled (2026-07-15) — The rendered DOM is not the document: emission serializes the doc, never scrapes the editor. Render-time marks never reach output; P3 binds the content, the working surface wears what it needs.
- **Structure selects itself** · settled — The anatomy and the document's own attributes are styling hooks: `thead tr`, `th[scope="row"]`, `[data-formula]`. Selectors *reading* content and automation is legitimate; the incumbent fakes with classes what our honest DOM answers natively.
- **CSS's honest share of formatting** · settled (2026-07-16) — CSS cannot format (no currency, no dates — that's `Intl`, §3); its share is *styling by type*: `[data-type="number"]` right-aligns, `tabular-nums` lines up digit columns. Formatting writes text; styling dresses it — the registers, again.
- **The interface state vocabulary** · pinned (2026-07-15) — Attributes with values, not class swarms, each entry naming its owner. *Document-borne* (serialized): anatomy, `scope`, `data-formula`, the future error mark. *Decoration-borne* (never serialized): `data-selected`, `data-editing`. *Wrapper-borne* (ephemeral): `data-mode`, `data-purpose`, the rulers, drag overlays. Exact names await the christening round.
- **The vocabulary is public API** · pinned — Theme authors select on these attributes; theming knobs ride CSS custom properties. Test: a theme that only sets custom properties can restyle every interface state.
- **Icons are presentation** · pinned (2026-07-15) — A glyph is its command's costume: meaning lives in the command and its `aria-label`; the icon is decoration (`aria-hidden`), an SVG data-URI in a custom property (`--spreads-icon-*`), applied via `mask-image`, painting with `currentColor`. Test: an icon-only button is never icon-only in the accessibility tree.
- **The icon set switches because the theme API already does** · pinned — Override the variables (an optional `icons` plugin option lands in the same variables — one mechanism, two entrances). A theme is a bag of variables: colors, cursors, glyphs.
- **Default icon set** · settled as direction — ~10 glyphs curated from Lucide (ISC, verified at adoption), embedded as data URIs, zero dependency; the `fx` badge likely styled text. A bespoke set can arrive later as just another theme.
- **Column width is document data, seated on `col`** · settled (UX round, 2026-07-20; the open resolved by its own test) — The ownership question closed by the undo question it had already asked: a user dragging a column edge is editing *their table*, so the width undoes — document-borne, as Excel holds widths. The seat is `table_col`'s `width` attr, emitted as `<col style="width:96px">`: each register now has its home in the document (content→text, automation→`td[data-formula]`, presentation→`col`), the emission renders true in any browser without our stylesheet, and the incumbent's pollution (per-cell `colwidth` leaking into every td) is refused — one column, one fact, one seat. Deliberate amendment to the pristine-emission test: the col width style is the *one* presentational fact in output, because it is the user's declared geometry, not stage makeup. A table whose colgroup declares widths wears `table-layout: fixed` — nothing breathes while typing; a table with no colgroup stays a fluid document table, and the first resize *carves* the colgroup into the document (P6: rigidity is paid for exactly when reached for). The carve snapshots every column's measured width in that same transaction so nothing jumps at settle; one undo step lifts the whole colgroup back out. The colgroup-truth portion arrived with the structure commands (2026-07-27): a column insert splices an undeclared col (`width: null`) at the matching index of the first colgroup, a delete removes it — same transaction, one undo step; inserts never create a colgroup (the first resize still carves it). C8's general shape-repair pass remains future duty.
- **The christening round's cargo** · open — command names, attribute names and values, `gridKeys`' spelling, icon names and human labels (the localization surface), error tokens (§10), and the format-spec notation (§3) baptize together.
- **Parked glimpse** — the CSS Custom Highlight API paints ranges with no DOM marks; wrong shape for cell rectangles, worth remembering for in-cell text painting.

## The frontier

### 8 · Names & ranges

How names bind, resolve, and survive edits (Tablet P5).

- **Ranges ride HTML header semantics** · pinned — carved as C4; the resolver *is* the spec's header-association algorithm (C14), filtered by region (next item), so `=SUM(Price)` and a screen reader agree by construction.
- **A name denotes its tbody cells — the anatomy is the data boundary** · settled (Egildo, 2026-07-17) — thead names, tbody is the data, tfoot speaks *about* the data: a column name resolves to tbody cells only, so the tfoot total never contains itself, and a formula inside tbody referencing its own column is honestly a cycle (C9). C4 refined: formulas and assistive tech read the same associations — AT hears "Prezzo" across the total row too — but the *name* quantifies over the data region; same names, narrower quantifier. Excel dodges self-reference because explicit ranges stop where you point; we don't point, so the anatomy does the stopping. Composes forward: with multiple tbodies a name means the union across row groups and slices narrow — v1 semantics survive the upgrade untouched.
- **The grain is declared, and formulas transpose for free** · settled (scope round, 2026-07-16) — Document tables are often row-major; `scope="row"` is HTML declaring the grain. Names never knew about axes: `=SUM(Weight)` over a *row* is the same resolver, no special case — where spreadsheets need TRANSPOSE agony. Likely the scope commitment's most practically-loved consequence (P6 showcase). A cell is a citizen of every range it belongs to, and dirty propagation fans out through each; the row-header cell is both a member of its column and the mint of its row's name — a coordinate basis, not a conflict.
- **Hierarchical named ranges** · pinned (C14) — `th scope="colgroup"` names a union of columns (`=SUM(2025)`); multiple tbodies with `th scope="rowgroup"` name dataset partitions (`=SUM(Price[Q1])`) — the original portions-of-datasets idea on the spec's own furniture. One grouping level each way, capped by the spec. Test: both forms resolve through the association algorithm with no plugin-invented names.
- **`col` is the seat of column-level automation** · open, the frontier's next big concept — `<col>` gives the phantom column an element: no text (names stay in th) but attributes — `data-formula` for calculated columns, `data-type` for typed ones, `data-format` for the column's format (third arrival at this seat). Cell-level override · open with it. Unruled, awaiting its round.
- **`abbr` is the reference name** · settled (2026-07-16, circled; source read: MDN on `th`) — The value/display split for names on the spec's own seat: th content is the human's full header, `abbr` the compact label — and screen readers already announce `abbr` at data cells, so the name a blind user hears and the name a formula speaks are the same string from the same attribute. Resolution rule: `abbr` wins when present, content otherwise. Rename propagation covers `abbr` edits.
- **The naming round, shrunk by `abbr`** · open — Long names: solved by spec furniture; collisions gain a legitimate escape hatch before we invent syntax. Remaining cargo: duplicates within an axis; **cross-axis collisions** (likely rule: bare names resolve if unique across both axes, else demand qualification); empty th; case and whitespace; qualified names for groups; coordinate-lookalike names (C16); and the rename machinery's edges — settle-on-commit gives the boundary where a th edit rewrites references pointing at it, IDE-grade rename from machinery built for other reasons, row renames included. Type discipline holds at the basis: `SUM` over a row-header column is a C9 type error, `COUNT` is fine.
- **The accessibility rhyme** · noted as a law-candidate (2026-07-16; four observations by 2026-07-18) — data/time for values, abbr for names, scope/headers for ranges, the region anatomy for the data boundary: whenever this design needs a machine-form/human-form split, HTML already built the seat, because accessibility needed it first. Not yet a stone; graduation gets its own moment.
- **Scaffolding references** · pinned (C16, 2026-07-15) — The adapter's lifecycle in one place: parse coordinate tokens at the boundary, resolve through the grid map, adjust in `appendTransaction` via transaction mapping, upgrade at naming through rename propagation. Serialized scaffolding refs are honest markup: they document the table's semantic immaturity and heal when maturity arrives. Grammar cargo for the naming round: the lexical rule for names that look like coordinates.
- **This-row contextual references** · open (surfaced by the fill-handle round) — `=Price*Qty` inside a data row meaning "at my row" (Excel's structured `[@Price]`, bolted on late there; native here). Makes fill-down literal copying and is the bridge to `col data-formula`. Needs its grammar rule in §9.
- **Parked glimpses** — `<output for>` as semantic wrapper for computed values; addressing as a citizen of the automation register; `<meter>`/`<progress>` as native-visualization format kinds (Excel's data bars as spec furniture); `<caption>` as the table's own name, waiting for cross-table formulas; **subtotals live in tfoot's multiple rows** (formula round, 2026-07-17) — a per-partition summary inside its tbody would sum its own range, and the cycle error is the design *teaching* where summaries belong: one tfoot row per partition plus the grand total, no double counting possible by construction — the answer Excel needed SUBTOTAL's contortions for; awaits the partition round.

### 9 · Formula language

The v1 cut landed and was built the same day (formula round + battleground 2, 2026-07-17): lexer, recursive-descent parser, five functions, two reference forms — live, suite-pressed, coordinate-free. Exact spellings await the christening round. Provisional in the build: a standing cell's raw value is its text parsed as a canonical number (§3's typed-value layer replaces exactly this seam).

- **The v1 language** · settled as scope (Egildo) — Number literals, `+ - * / ( )` with unary minus, five functions: `SUM`, `AVG`, `MIN`, `MAX`, `COUNT` — the manual's claim, held; the smallest language that writes every formula in the manual's showcase. No conditionals, strings, dates-in-formulas, or volatiles; the set grows by rounds, never by drift. Open inside the cut: `COUNT`'s exact meaning (non-empty? numeric?).
- **v1 reference forms** · settled as scope — Bare `Name` (column or row — the grain makes them one machinery) and the intersection `Col[Row]`. Group unions and partition slices fall out of v1 *naturally* — they need spanning headers, already forbidden on the merged-cells side; the cut lands on a seam that was already there. This-row references wait for the col-automation round.
- **Names lex as bare identifiers; spaces demand an `abbr`** · settled (formula round) — No quoting syntax invented: the escape hatch is the spec's own furniture, and the manual's example (`abbr="Prezzo"`) implied the rule before it was spoken. Grammar cargo from C16 stands: the lexical rule for coordinate-lookalike names.
- **The serialized grammar is canonical and invariant** · settled (formula round) — Dot decimal, comma separators, locale-independent: a formula lives in an attribute and must survive crossing documents and locales; Excel's localized formula texts are the famous wound, refused. Display-side localization, if it ever comes, is presentation and breaks nothing.
- **The full reference grammar, sketched by the spec for later** (C14): `Col[RowGroup]` (partition slice), `GroupName` (union), `Col[R1:R2]` (span slice), qualified names (`2025[Jan]`), the this-row form (§8). Ambiguity rules belong to the naming round. **The kernel grammar contains no coordinate tokens** (C16): the adapter extends the grammar at its own boundary, so a strictly-semantic deployment has zero positional ambiguity by construction.

### 10 · Evaluation & validation

How declarations become true, and what happens when they can't. Surveyed 2026-07-15: Excel's recalculation documentation; HyperFormula's dependency graph.

- **The evaluation model** · pinned; first form built (battleground 2) — A dependency graph over resolved references with named ranges as first-class nodes (HyperFormula's insight, natural under semantic addressing: a formula depends on the *name*; membership changes dirty the range while references stay whole). On settle: evaluate within the dispatch, each cell visited exactly once. Built form, the economical reading: memoized descent with a visiting-set for cycles, and a *conservative* dirty set — any document change recomputes every formula cell (idempotence stops re-entry; each cell still visited once, the pin's test holds); precision dirty-marking arrives when table sizes demand it. Observed and embraced: enforcement rides the *undo* too, recomputing totals for restored data — doctrine over cache, no observable state disagrees with its inputs.
- **Cycles are errors, not iterations** · settled — Detected at settle, produce an error value; no iterative mode. Excel ships one; economy says no.
- **No volatile functions in v1** · settled — Functions are pure over cell values; volatiles are poison under settle-only recompute. Reopening requires a recompute-trigger design first.
- **Evaluation is synchronous and bounded** · settled — It runs in the dispatch path; no async automations in the enforcement path, ever. Async, if it comes, computes outside and dispatches a settle.
- **Errors are values** · settled; first tokens live (battleground 2) — A typed error value occupies the cell, propagates, and serializes — truth extends to failure. Live tokens: `#NAME?`, `#CYCLE!`, `#DIV/0!`, `#VALUE!` (the text-in-an-aggregate trap we refuse; a token the manual never listed — christening cargo). Provisional wart: an unparseable formula settles to `#NAME?` — refusal at the seam is the better design, waiting for its UI round. `#REF?` has no v1 producer (a deleted column is an unknown name here, not a dangling coordinate). **Error markup** · open, promoted to pre-v1 gate — errors serialize, so `#CYCLE!` needs its P2-worthy costume before v1 ships; its own small round.
- **Two species of validation, kept apart** · pinned — Resolution errors (automation failing) versus data validation (content violating declared expectations). Spreadsheets silently skip text inside SUM — a trap we refuse. Glimpse, parked: typed columns as declarations the plugin keeps true (§8).
- **Adopt vs build** · settled by the probe (battleground 2) — Built small: lexer, parser, and evaluator total a few hundred dependency-free lines with zero coordinate code (C16's purity by construction); HyperFormula's A1-centric machinery had nothing left to sell beyond the graph shape, already stolen.
- **The C16 adapter is release cargo, not kernel cargo** · noted — C11's bottom step makes the adapter part of the release story; it fights in its own battleground after the kernel.
