# The Architecture — second edition

Design decisions descending from [the Tablet](tablet.md). Two layers: **the consequential choices** — the spine, each naming its parent principles — and the **working sections**, organized along the seam map and structured as the complete implementation description even where content is still stub. Marks: settled / pinned / open, per the Tablet; depth annotations (circled / ratified on briefing / proposed, unruled) record how deep the round was that produced each claim. Nothing here has met code yet; the marks say so and the rewrite keeps them saying so. First edition's accretion history lives in the changelog (edition note, 2026-07-15).

**The seam map.** Four seams, declared so no round welds across one: **the factory** (schema, §1), **the core** (engine, state, commands, interaction, node views, §2–§6), **the chrome** (presentation, rulers, icons, §7), **the frontier** (names, formula language, evaluation, §8–§10), plus **the borders** (serialization, collaboration, testing, §11–§13). The classic failure the map guards against: the core quietly importing the evaluator. Whether the seams become separately installable plugins is C15's open round.

## The consequential choices

Condensed from the circled rounds of 2026-07-14/15; the layer's ordering and C2, C5, C11 (and the Tablet's P4) are ratified on briefing — direction, not gospel. The parentage rule is self-auditing: a choice that cannot name its parents is either unjustified or reveals a missing principle (it found P4).

- **C1 — The document is the sole truth; ProseMirror is the transactional store** (P1) · settled — Everything the table *is* lives in the doc; everything ephemeral — buffers, hovers, drags, selections — lives in the view layer and dies there. Inside tables, ProseMirror is our document engine, not our text editor: cells are atoms with node-view surfaces. The named bet, accepted.
- **C2 — The anatomy is structural** (P2) · settled, ratified on briefing — `thead`, `tbody`, `tfoot`, `caption` are node types, not serialization garnish. Boundaries have editing meaning: moving a row into thead is a promotion, not a reorder.
- **C3 — Every fact sits in its register's seat** (P3) · settled — Value in element content, automation in attributes, presentation in constructed stylesheets. `<td data-formula="=SUM(Price)">42</td>`; standing cells pristine; the stylesheet is the only presentation channel.
- **C4 — Names come from the content** (P2, P3) · pinned — Scope'd headers name columns and rows; formulas and slices speak those names; automation borrows names the content earned, never invents its own. No positional notation exists above the engine room. Test: `=SUM(Price)` resolvable from standard, valid markup alone.
- **C5 — Positions live below deck** (corollary of C4) · settled — Geometry machinery is internal; positions never appear in notation, document, or the user's vocabulary. The resolver translates gestures (positions) into sentences (names).
- **C6 — Two modes, one seam** (P4, C1) · pinned — Grid mode: cells as units, custom selection, the cross cursor. Edit mode: one cell's buffer. Commit is the seam, doing three jobs — mode boundary, evaluation trigger, undo grouping.
- **C7 — The gesture law** (P4; generalizes C6) · pinned — Everything continuous streams in the ephemeral layer; state changes atomically at seams. Cell edits settle as one transaction; drags stream and settle at pointerup; the pointer's purpose is computed state, the cursor its costume.
- **C8 — Enforcement is declaration-keeping, with two duties** (P3, P5) · settled; second duty added from the incumbent survey, 2026-07-15 — The engine makes the document true in both registers: it keeps the **shape legal** (structural normalization — ragged rows, colliding spans, wreckage from paste and collab repair into legal anatomy; the incumbent's `fixTables` proves the duty and the seat) and it keeps the **declarations true** (on settle: dirty-mark, evaluate topologically over the name graph, one dispatch — synchronous, bounded, no volatiles, cycles are errors). Both duties seat in `appendTransaction`; the cascade rides the settle (Egildo's economy ruling).
- **C9 — Errors are values** (P2, C8) · settled — Failure occupies the cell, propagates through dependents, and serializes: the markup admits what broke. Two validation species kept apart: resolution errors (automation failing) and data validation (content violating declared expectations).
- **C10 — Collab bends, doctrine doesn't** (C8) · settled as ruling — Cell-wise atomicity is accepted over collaborative perfection; the mitigation — recompute rides the originating transaction — stays pinned until proven.
- **C11 — Semantics are rewarded, never gated** (P2, P5, P6) · settled (2026-07-15, circled; supersedes the proposed "no names, no formulas" form, whose cliff contradicted C14's own guard) — An anonymous table is a fine table with every capability's bottom step: scaffolding formulas (C16) work from day zero. What names buy is durability and meaning — references that survive every edit, markup that says what it computes. The fat ruler and fragile positional refs are the face of an unnamed table, and the interface actively offers the upgrade. Semantics pay; they never gatekeep.
- **C12 — Everything is a command** (P1) · settled (Egildo) — Every mutation is a ProseMirror command: composable, keybindable, dry-runnable (call without dispatch — menu enabling for free), testable headless. UI never mutates; it invokes. The command vocabulary is the plugin's verb list and the manual's future words.
- **C13 — The view is downstream** (C1, C12) · settled (Egildo) — command → transaction → doc → derived indexes → node views. Node views are renderers and input surfaces, never truth-holders; their ephemeral state becomes real only by dispatching through the front door. A node view that makes decisions is a smell.
- **C14 — The spec is the contract: ceiling, never floor** (P2, C2, C4) · settled (Egildo) — The full HTML table model is in scope: `caption`, `colgroup`/`col`, `thead`, multiple `tbody` row groups, `tfoot`, all four `scope` values, `headers` overrides; the resolver implements the spec's header-association algorithm, so formulas and assistive tech read the same table by construction. **Supported is never required** (Egildo's guard): the bare-tbody table is first-class; capability grows monotonically with markup — never a cliff. Survey duty discharged (battleground 2, 2026-07-17; spec text read): "the header cell applies to some of the **subsequent** cells" — subsequent is load-bearing (headers name only what follows them), and scope=col crosses row groups including tfoot, confirming the accessibility/name split of §8's region filter. Test: every command except formula-entry applies to a table with zero named columns and rows.
- **C15 — The seams may become packages** (C11, C14; incumbent survey) · proposed, unruled — The incumbent survived a decade as a family (core plugin + optional plugins + schema factory), not a monolith. Our capability gradient suggests the same shape: factory + core + chrome + frontier — plus the scaffolding adapter (C16's training wheels) — as separately installable capabilities, making C11 true at the package level. Nothing settled binds across a seam yet; its own round before anything does.
- **C16 — Queries in the kernel, coordinates on the ring** (C4, C5, P6) · settled (2026-07-15, circled) — Kernel references are semantic queries: a name resolves the way a selector does, through the association algorithm — no selector could ever match `A1:B1`, because a coordinate describes grid geometry, not the document. Positional notation therefore never enters the kernel: a **boundary adapter** owns its whole lifecycle — parse the coordinate token, resolve it via the grid map, adjust it through structural edits (bounded: ProseMirror's transaction mapping does the heavy lifting), and upgrade it to a name the moment one exists (the rename machinery). The scaffolding tier of incremental elegance (P6), never a co-equal second system — Excel's permanent-two-notations wart is the refused road. Candidate separate package under C15. Purity test: delete the adapter and every named formula still works; the evaluator's source contains no coordinate code.
- **C17 — The table is a black box to the editor view** (P1, P4, C1, C13) · settled as direction (capriccio, 2026-07-18, Egildo; battleground 3 to confirm; source read: the PM guide's own sentence — without `contentDOM`, "the content becomes a black box to the editor") — One table-level node view owns the entire grid DOM; inside it there is no contenteditable — native inputs, roving tabindex, the ARIA grid pattern. The document stays the sole truth and every mutation stays a command riding a transaction: P1 is untouched state-side; what changes hands is only the renderer. Rows and cells re-render through a keyed-by-node-identity diff (the WeakMap-memo trick, applied to DOM), so the named bet's soul — node-view-owned buffers — survives; what's discarded is ProseMirror's skeleton sync, which is where both battleground-1 dragon families lived. The boundary shrinks from N cells to one door, and at the root it kills: DOM-reader mangling, selection leakage into cells, keymap-ordering fragility, and the focus dance's very cause. Never gets built: the CellSelection machinery — grid selection becomes view and plugin state, not a Selection class. Accepted costs, named: third-party decorations don't render inside tables (mitigated: presence is already cell-grained under settle-on-commit and rides our attribute vocabulary; the CSS Custom Highlight glimpse covers range painting), paste inside the table is self-hosted (C8 wanted paste normalization anyway), and the scalar-cell commitment hardens (§1). Pinned tests: a buffer survives a remote redraw under our own diff; the accessibility tree reads as a grid; emitted markup is byte-identical to today's; plugins outside tables — decorations included — are unaffected. The current cell-level design stands until battleground 3 wins.

## The factory

### 1 · Document schema

What a table *is* in the ProseMirror document.

- **The node set** · settled (C2, C14) — `caption`, `colgroup`/`col`, `thead`, `tbody` (repeatable — row groups are real structure), `tfoot`, rows, `td`/`th`. Content expressions make everything beyond `tbody+` optional — `caption? colgroup* thead? tbody+ tfoot?` — so the bare-tbody table is first-class (C14's floor).
- **The schema is a factory; the names are contract** · pinned; names ruled settled (audit round, 2026-07-17, Egildo) — Consumers have schemas we've never seen; node specs are generated by a function (the incumbent's `tableNodes(options)` posture) and plugin code locates types by role (its `tableRole` pattern), never by dispatching on names. But the names themselves are part of the package contract, appended as-is — not parameters (the audit found the renaming claim half-kept: the `nodeViews` prop is name-keyed by nature, and the incumbent's decade proves fixed names suffice). Roles remain internal discipline and a discoverability hook. Deliberate consequence, named: our names collide with prosemirror-tables' — one table system per schema, the seat is taken. The known door if coexistence or renaming ever becomes real (the scenario: gradual migration from the incumbent): `spreads({schema})` resolving node-view keys by role — marked, not built.
- **Computed-cell serialization** · settled as shape, open in detail — `<td data-formula="=SUM(Price)">42</td>`; standing cells pristine, zero plugin fingerprints. Open: the attribute's name (one `data-formula`, or a family as P5 grows), and the parked `<output for>` glimpse (§8).
- **Typed-cell anatomy and emission** · settled (2026-07-16, circled; sources read: MDN and the WHATWG spec on `data`/`time`) — The document model stays scalar: raw value, type, and format are cell-node attrs. Emission wraps: `<time datetime="…">` for temporal values (MDN: must), `<data value="…">` for the rest — the spec's canonical `data` example is literally our use case, numeric table cells wrapped so a computing script can read values while humans read text. `td` contributes the WHERE (a cell, header-associated), the wrapper the WHAT (machine translation of this text) — no pleonasm, two axes. Parse accepts wrappers and flat `data-*` alike. Untyped standing cells stay pristine text — P6's zero tax. Test: a typed table round-trips through emission and parse without losing value, type, or format.
- **Cell content: scalar vs inline markup** · open, hardened by C17 — Settle-on-commit (§5) pins to scalar cells; the emission wrappers above are toDOM's business, not model content, so the pin stands. P2's beautiful `<td>` sometimes carries a link, `<code>`, `<abbr>`; the day a cell legitimately needs inline markup, the design comes back up rather than getting a workaround — and under the black-box destination that day costs more: rich cell content means rendering inline markup ourselves or the nested-mini-editor pattern. The door stays marked, heavier.
- **Rows are mixed** · settled (scope round, 2026-07-16) — A `scope="row"` th lives inside tbody rows: content expressions allow header cells in body rows. Open with it: multiple row-header cells per row (two-level row headers, legal HTML) — v1 instinct caps at one until the groups round.
- **No formulas on th** · settled (v1 constraint, scope round) — A computed *name* would make the range's identity depend on other cells' values — a self-describing graph. Parked hard until something real demands it; th cells are standing values.
- **Merged cells** · open, instinct recorded — v1 forbids merged data cells; spanning headers (`scope="colgroup"`/`"rowgroup"`) wait for their own round.
- **Residue** · open — Exact content expressions; span constraints (one grouping level each way; cells cannot span across row-group boundaries — the spec forbids the nastiest geometry case); `caption` details.

## The core

### 2 · The engine room — derived indexes

No stored model, ever (C1 descended): the node tree is the structure; the engine room holds indexes — derived, disposable, rebuilt on demand. A stored cell-object model would recreate the two-truths problem inside the plugin.

- **The grid map** · pinned; first form built (battleground 2, 2026-07-17) — A flat width × height slot array holding the document position of each covering cell; spanning cells occupy multiple slots. Every 2D question becomes index arithmetic. The incumbent's `TableMap` shape, stolen whole — including its **problems array** (survey, 2026-07-15): the map diagnoses structural illegality as a by-product of the geometry pass, feeding C8's normalization duty. The built form adds **per-row region metadata** (head/body/foot plus section index) because the data boundary is a region question (§8), and reports ragged rows; v1 schema mints no spans, so the span machinery is unbuilt and the pin's spanning-cells test still waits.
- **Memoized by node identity** · pinned — Persistent nodes make an unchanged table the same object across doc versions; indexes cache in a WeakMap keyed by the table node (the incumbent's exact mechanism, verified in source). No invalidation logic; every historical doc version produces its correct map, so undo/redo/collab work on indexes for free. Rebuild is O(cells); incremental maps are a deferred optimization with a known shape.
- **The name table and dependency graph** · pinned; first form built (battleground 2) — Names → cell sets (from scope'd headers, via the association algorithm, C14); formula cells → name nodes; group names contain member-name nodes (§10). Derived and memoized the same way. The built form: abbr wins, bare identifiers only, tbody-filtered, the spec's "subsequent" honored; duplicates mark both entries ambiguous and referencing one is a resolution error (v1 provisional, naming-round cargo). The dependency graph is *implicit* in v1 — memoized descent discovers dependencies during evaluation rather than storing edges; the explicit graph arrives when incremental recompute demands it.
- **Structural operations are document surgery** · settled — Insert row/column: a transaction inserting nodes; references survive by C4 (the range node's membership grows — no formula rewrites). Promotion into thead/tfoot: move the `tr` across the boundary, retype `td ↔ th` with scope, one transaction. Indexes never participate; they rebuild after. The hard consequences are semantic (names minted or orphaned) — seated in the naming round (§8).

### 3 · Plugin state & enforcement

What the plugin's own state holds — and refuses to hold (derivables belong to §2; ephemera to the view layer).

- **Formula as attribute, value as content** · settled (2026-07-14, circled) — The formula is automation (Tablet P3) in an attribute; the `<td>` contains the computed value as real content. Content is the data — readers, scrapers, screen readers get `42`; the attribute is the provenance. Supersedes the coach's decoration-based cut, which lost because serialized output would have shown formulas where readers wanted data. Rhyme as evidence: XLSX stores formula plus cached value for the same reasons.
- **Format is a declaration** · settled (2026-07-16, circled) — A formula declares how a cell's *value* derives; a format declares how its *text* derives from the value: `content = format(value, spec, lang)`, enforced in the same dispatch, by the same engine, as formulas. The full cell anatomy: raw value in an attribute (machine's truth), formatted text in content (reader's truth), declarations explaining both. The evaluator computes on raw values only — it never parses display text. Formatting is `Intl`'s job under inherited `lang` (deterministic: declaration plus lang is a pure function; no viewer-dependent content). Open: the format-spec notation (Intl vocabulary — christening cargo, §7) and the locale road's edges (no-`lang` default undecided).
- **Enforcement seats in `appendTransaction`, both duties** · pinned (C8, formulas and formats alike) — Shape kept legal (normalization: the fixTables analog, ours harder — "legal" includes regions) and declarations kept true (recompute of dependents, reformat of their text, in the same dispatch). Test: after any single user action, no observable editor state shows an illegal table or a formula cell disagreeing with its inputs.
- **Selection legality is part of the shape duty** · settled (battleground 1, 2026-07-17) — A caret inside an atom cell must be unrepresentable: ProseMirror's DOM reader parses node-view-owned cell DOM it cannot understand, and the table mangles (observed twice in the probe: a double-click's second click, and undo restoring a mapped text selection into a cell). Two entrances, both guarded: `createSelectionBetween` coerces view-derived selections and `appendTransaction` coerces state-level ones (undo/redo arrive there) to the cell's node selection — the enforcement engine's first working piece, seated exactly where C8 said it would live.
- **Stale-value rule** · pinned; implemented (battleground 2) — A cold-parsed value disagreeing with its formula loses; the value is cache. Seated in the plugin view's mount pass (one enforcement run, outside history — undo must not restore staleness); headless, the first dispatch does the same job. Test: loading fixture HTML with a stale cached value recomputes it without touching anything else.
- **The state model: cell-wise atomic updates with cascade** · settled (2026-07-15, Egildo's ruling) — The unit of state change is the settle: one cell's atomic update plus automation side effects, one dispatch. Collab complications accepted as known cost (§12).
- **To verify — nothing may lean on these yet** · open, two of three now verified (battleground 2, 2026-07-17) — (a) **verified**: a settle with its appended recompute cascade undoes as one event, and undoing a demote restores formula and content together (headless tests hold both; the `newGroupDelay` caveat from battleground 1 stands); (b) **verified**: transitive dependents chain (`=SUM(B)+1` over `=SUM(A)*2`), cycles detected including a formula inside its own column's range; (c) paste into a computed cell — still open.
- **The mode field's first form** · settled (battleground 1) — Plugin state holds the edit seam and nothing else: `editing: {pos, seed} | null`, the cell position mapped through every transaction while the buffer is open, dying if the cell is deleted; `seed` carries type-to-replace's first keystroke. Commands move it via metas (`startEditing`/`stopEditing`); the settle command clears it in the same transaction as the content change.
- **Stub** — grid-selection state, dirty bookkeeping: seated when the selection round and the frontier land.

### 4 · Commands — the verb list

Every mutation is a command (C12); this list is the plugin's public verbs. Sketch, unbaptized — names await the christening round:

- Structure: add/delete row and column (before/after), move row/column.
- Regions: promote row to thead / demote; promote to tfoot; make a column the row headers.
- Cells: settle (the one seam); demote formula cell to standing value; fill (copy / series / formula, from the fill handle, §5); merge/split (deferred with §1's merged-cells question).
- Selection & navigation: select row / column / table; arrow-walk in grid mode; enter/leave edit mode.
- **Stub** — signatures, applicability rules, keymap: after the schema residue round.

### 5 · Interaction layer

Spreadsheet-grade editing (P4) — modes, gestures, selection.

- **Settle-on-commit** · pinned (2026-07-14) — Cell edits settle as single transactions at commit (Enter / Tab / focus leaving); mid-edit text is node-view-owned UI state — "like somebody pasted a few chars". The buffer shows the formula for formula cells, the *lexical* value for standing cells (grid shows formatted content; you edit "1234,56", never "€ 1.234,56"); settle parses input by type and locale, and what refuses to parse is caught at the seam — validation's second species with teeth, never silent corruption. What it buys, named because argued: native IME, cell-granular collaboration, one undo event per settle, and the death of cross-cell text selection (a word-processor hideousness, replaced by grid selection). Pinned to scalar cells (§1). Probe finding (battleground 1, 2026-07-17): the interception seam is `beforeinput`, not keydown — IME and synthetic input paths never send a keydown, and unintercepted text over a selected atom cell falls through to ProseMirror's node replacement, which splits the table; type-to-replace therefore seeds the buffer from both entrances (keydown for keys the buffer owns, beforeinput for everything that writes).
- **Grid and edit modes** · pinned — Grid mode: cells as units, arrow keys walk cells. Edit mode: caret inside one cell's buffer. Commit is the seam (C6).
- **The purpose model** · pinned (2026-07-15) — Nobody sets a cursor: the plugin computes the pointer's purpose — what a pointerdown would mean here — as a pure function `(mode, zone, modifiers) → purpose`, testable headless. Zones from hit-testing (closest cell + rect edges; the map disambiguates spans). The cursor is the purpose's costume: `data-purpose` on the wrapper, mapped in the constructed stylesheet (CSS ships `cursor: cell`, `col-resize`, `row-resize`). Purpose changes only on zone transitions; hover state is ephemeral. Open fork: view-local variable vs plugin-state mirror — probe territory; the incumbent chose plugin-state via meta transactions (survey, 2026-07-15), shifting the prior.
- **The gesture law** · pinned (2026-07-15) — Continuous in the ephemeral layer, atomic at the seam: `setPointerCapture` owns drags, feedback streams without transactions (resize streams into the sheet via `replaceSync`), one settle at pointerup. The incumbent's resize independently converged on preview-then-settle (survey) — it just spends per-move meta transactions where we spend none.
- **The rulers — scaffolding that recedes** · pinned (2026-07-15, Egildo's design) — A fresh table wears classic rulers: A B C / 1 2 3, wrapper-owned overlay chrome, sticky, never document content. Labels are **wayfinding first, scaffolding second**: with the C16 adapter installed they become speakable coordinates at the bottom step, upgraded away at naming; the durable line holds — no coordinate is kernel material, and none survives a naming. When a thead arrives, th cells inherit the identity duties (label, click-to-select) and the ruler minimises to the mechanical strip (drag, resize grips, context menu, add/delete). Recede is per-column — a letter returns for any empty th; scaffolding is exactly as big as what's still unnamed. The fat ruler carries the promotion affordance: using it is what minimises it. Rows symmetric via `scope="row"`, and may honestly never minimise; an inserted row with an empty header cell wears its ruler number until named — per-row scaffolding, the recede law running sideways. Header editing keeps the grid grammar: click selects, Enter/double-click dives.
- **The fill handle** · pinned (2026-07-15, no-dependency verdict) — The lil square: a wrapper-owned overlay at the selection's corner, one purpose-zone (`fill` → native `cursor: crosshair`; the grid's fat cross is native `cursor: cell`), gesture-law drag (axis-dominance is pure geometry against the map, preview streams, zero transactions), one `fill` command at pointerup. No dependency buys anything we don't already have. Under semantic references, **filling a formula is literal copying** — Excel's relative-reference rewriting machinery doesn't exist here (C4's kill, again); a this-row reference (§8) copies unchanged. Fill-to-column-bottom is the natural on-ramp offering "make this the column's rule" (`col data-formula`, §8) — the gesture teaching the declaration, chrome dissolving into semantics (P6). Series scope · open: v1 instinct is copy plus linear numeric; dates and weekday lists drag in localization, parked. Touch-target size belongs to the UX campaign.
- **Selection model** · stub, road changed by C17 — Grid selection is view and plugin state, never a custom Selection class: the incumbent's `CellSelection` (verified in source: anchor/head cells, rectangular ranges, decoration-drawn, remapping through structure changes) was the pattern to adopt under the old skeleton, and the black-box ruling closes that road — its jobs (rectangles, drawing, remapping) become the table view's and the plugin state's. Headers double as selection gutters; the resolver translates rectangles into names during formula-building. **Mid-drag remote transactions** must still remap the drag's anchor (survey; thread to §12) — the duty survives the ruling, seated in plugin state. Waits on the semantic-selection UX campaign.
- **The keymap-ordering contract** · interim law (audit, 2026-07-17) — While the current design stands, `spreads()` precedes any keymap binding keys meaningful in grid mode: plugin order is ProseMirror's only priority system, and a preceding `baseKeymap` deletes a selected cell outright (`deleteSelection`; demonstrated live in the audit). At the C17 destination the contract mostly dissolves — the box owns its keys. Thread: the audit's Finding 2, its landing pending.
- **Value XOR formula** · open (Egildo's mark: "we'll see") — A cell is a standing value or a formula, never both. Battleground 2 implements the manual's trial behavior: "=" as first character makes the cell a formula, plain text over a formula cell demotes it (attribute removed, same settle transaction), the buffer shows the formula while the grid shows the value. Working code is not a ruling; the mark stays open until Egildo closes it.
- **Semantic-selection UX campaign** · open — The model is sound (selection = gesture in positions; reference = sentence in names); the gestures are unproven; a mixed UI approach is expected (Egildo). Its own playground campaign.

### 6 · Node views

The custom editing surface — the only region not testable headless.

- **The named bet** · pinned; **first probe passed** (battleground 1, 2026-07-17) — Cells as atoms with node-view-owned buffers: ProseMirror as transactional store, not text editor, inside tables. Legitimate machinery, but the incumbent chose the opposite, and everything leans on this. The dragon: the focus dance, and node views surviving redraws mid-edit (a remote change to a *neighboring* cell must not destroy the buffer). The probe pressed both and the bet held: buffers survived a remote change to a neighbor and a position-shifting change before the table (the editing pos maps through), focus never blinked; the focus dance works with a microtask-deferred grab after ProseMirror's DOM sync, and settle/cancel refocus the grid. The pin stays until real IME and real collab press it — and one guard is in the code: a cell view constructed while its cell is being edited reopens the buffer from the document, so a mid-edit view recreation (never observed in the probe) fails loudly rather than silently. **Destination update (C17)**: cell views become internal renderer components of the one table view; the buffer doctrine carries whole, while the focus-dance machinery is boundary scaffolding the destination dissolves — outside contenteditable, focus needs no dance.
- **Thinness discipline** · settled (C13) — Node views render consequences and host inputs; all intelligence lives in plugin state and pure functions.
- **The cell view's first anatomy** · settled (battleground 1) — The view owns a bare `td`/`th` whose text it renders itself (no `contentDOM`: the atom's inside is opaque to ProseMirror), and in edit mode hosts a native `<input>` — IME, spellcheck, autocorrect belong to the platform. Edit mode is read from plugin state, triggered by the `data-editing` decoration forcing the update; `stopEvent` claims exactly the events targeting the buffer; `ignoreMutation` claims everything. Enter/Tab/Escape live on the buffer; blur settles (a click elsewhere commits, like every spreadsheet).
- **Stub** — the overlay layer, the adopted sheet handle on the wrapper, richer `update()` contracts. Filled as the chrome rounds land.

## The chrome

### 7 · Presentation layer

The one channel (C3): a constructed stylesheet, and the vocabulary it selects on.

- **Constructed stylesheets as the one presentation channel** · pinned — A `CSSStyleSheet` owned by the plugin view, `replaceSync` on update, adopted by the document. Test: emitted markup of any table contains zero presentational attributes, styles, or classes, and the table still renders styled. Unchanged by C17: the black box changes who writes the DOM, not how it dresses — P3's channel is the same sheet either way.
- **Chrome lives inside the box** · noted under C17 (2026-07-18) — At the destination, rulers, overlays, the fill handle, and the conjured colgroup are plain DOM inside the table view's own subtree: no decoration plumbing, no wrapper tricks. The stage-makeup distinction does the same work it always did — the working surface wears what it needs, emission serializes the doc.
- **The stage-makeup distinction** · settled (2026-07-15) — The rendered DOM is not the document: emission serializes the doc, never scrapes the editor. Render-time marks never reach output; P3 binds the content, the working surface wears what it needs.
- **Structure selects itself** · settled — The anatomy and the document's own attributes are styling hooks: `thead tr`, `th[scope="row"]`, `[data-formula]`. Selectors *reading* content and automation is legitimate; the incumbent fakes with classes what our honest DOM answers natively.
- **CSS's honest share of formatting** · settled (2026-07-16) — CSS cannot format (no currency, no dates — that's `Intl`, §3); its share is *styling by type* through the constructed sheet: `[data-type="number"]` right-aligns, `font-variant-numeric: tabular-nums` lines up digit columns. Formatting writes text; styling dresses it — the registers, again.
- **The interface state vocabulary** · pinned (2026-07-15) — Attributes with values, not class swarms, each entry naming its owner. *Document-borne* (serialized): anatomy, `scope`, `data-formula`, the future error mark. *Decoration-borne* (never serialized): `data-selected` on cells and whole rows (values distinguish anchor from member), `data-editing`. *Wrapper-borne* (ephemeral): `data-mode`, `data-purpose`, the rulers (§5), drag overlays. Exact names await the christening round.
- **The vocabulary is public API** · pinned — Theme authors select on these attributes; theming knobs ride CSS custom properties. Test: a theme that only sets custom properties can restyle every interface state.
- **Icons are presentation** · pinned (2026-07-15) — A glyph is its command's costume: meaning lives in the command and its `aria-label`; the icon is decoration (`aria-hidden`), an SVG data-URI in a custom property (`--spreads-icon-*`), applied via `mask-image`, painting with `currentColor`. Test: an icon-only button is never icon-only in the accessibility tree.
- **The icon set switches because the theme API already does** · pinned — Override the variables (an optional `icons` plugin option lands in the same variables — one mechanism, two entrances). A theme is a bag of variables: colors, cursors, glyphs.
- **Default icon set** · settled as direction — ~10 glyphs curated from Lucide (ISC, verified at adoption), embedded as data URIs, zero dependency; the `fx` badge likely styled text. A bespoke set can arrive later as just another theme.
- **Column width ownership** · open, promoted — Content or presentation? The incumbent stores `colwidth` in cell attrs (and leaks it into output as `data-colwidth` — verified in source, the exact violation P3 forbids) yet *renders* widths through a colgroup element it conjures in its node view (survey, 2026-07-15) — evidence that col elements are the width mechanism either way, and our col-in-the-constructed-sheet candidate is the same mechanism minus the document pollution. But a user dragging a column edge feels like editing *their table*: does a width undo? First place P3 meets reality; resize mechanics blocked behind it. Its own round, soon.
- **The christening round's cargo** · open — command names, attribute names and values, icon names, their human labels (the localization surface), and the format-spec notation (Intl vocabulary, §3) baptize together.
- **Parked glimpse** — the CSS Custom Highlight API paints ranges with no DOM marks; wrong shape for cell rectangles, worth remembering for in-cell text painting.

## The frontier

### 8 · Names & ranges

How names bind, resolve, and survive edits (Tablet P5).

- **Ranges ride HTML header semantics** · pinned — carved as C4; the resolver *is* the spec's header-association algorithm (C14), filtered by region (next item), so `=SUM(Price)` and a screen reader agree by construction.
- **A name denotes its tbody cells — the anatomy is the data boundary** · settled (Egildo, 2026-07-17) — thead names, tbody is the data, tfoot speaks *about* the data: a column name resolves to the column's tbody cells only, so the manual's own tfoot total `=SUM(Prezzo)` never contains itself, and a formula inside tbody referencing its own column is honestly a cycle (C9). The precise refinement of C4's promise: formulas and assistive tech read the same associations — a screen reader crossing the total row still hears "Prezzo" — but the *name* quantifies over the data region only; same names, narrower quantifier. Excel dodges self-reference because explicit ranges stop where you point; we don't point, so the anatomy does the stopping — C2 paying rent again. The ruling composes forward: with multiple tbodies a name means the union across all row groups and partition slices narrow — v1 semantics survive the upgrade untouched, monotonic growth.
- **The grain is declared, and formulas transpose for free** · settled (scope round, 2026-07-16) — Document tables are often row-major (comparison tables, spec sheets — field names down the left edge); `scope="row"` is HTML declaring the grain. Names never knew about axes: `=SUM(Weight)` over a *row* is the same resolver, same graph, no special case — where spreadsheets need TRANSPOSE agony. For a plugin living among documents rather than ledgers, likely the most practically-loved consequence of the scope commitment (P6 showcase). A cell is a citizen of every range it belongs to — column, row, groups — and dirty propagation fans out through each (§10's graph was built for this); the row-header cell is both a member of its column and the mint of its row's name — not a conflict, a coordinate basis.
- **Hierarchical named ranges** · pinned (C14) — `th scope="colgroup"` names a union of columns (`=SUM(2025)`); multiple tbodies with `th scope="rowgroup"` name dataset partitions (`=SUM(Price[Q1])`) — the original portions-of-datasets idea on the spec's own furniture. One grouping level each way, capped by the spec. Test: both forms resolve through the association algorithm with no plugin-invented names.
- **`col` is the seat of column-level automation** · open, the frontier's next big concept — `<col>` gives the phantom column an element: no text (names stay in th) but attributes — `<col data-formula="=Price*Qty">` declares a calculated column, `<col data-type="number">` the typed column, `<col data-format="currency:EUR">` the column's format (third arrival at this seat: calculated columns, typed columns, now formats — real data tables type by column). Cell-level override of col-level declarations · open with it. Unruled, awaiting its round.
- **`abbr` is the reference name** · settled (2026-07-16, circled; source read: MDN on `th`) — The value/display split for names, on the spec's own seat: th content is the human's full header, `abbr` is the compact label — and screen readers already announce `abbr` when reading data cells, so the name a blind user hears crossing a column and the name a formula speaks to sum it are the same string from the same attribute. C4's promise deepens: formulas and assistive tech don't just read the same table, they speak the same names. Resolution rule: `abbr` wins when present, content otherwise. Rename propagation covers `abbr` edits — one more declaration changing at a settle.
- **The naming round, shrunk by `abbr`** · open — Long names: solved by spec furniture. Collisions: the user gains a legitimate escape hatch (set an `abbr`) before we invent disambiguation syntax. Remaining cargo: duplicates within an axis, **cross-axis collisions** (a column `Q1` and a row `Q1` — likely rule: bare names resolve if unique across both axes, else demand qualification; the round's to settle), empty th, case and whitespace, qualified names for groups, coordinate-lookalike names (C16), and the rename machinery's edges (settle-on-commit gives the boundary where a th edit rewrites references pointing at it — IDE-grade rename from machinery built for other reasons; row renames included — `Q1` → `Q1-2025` rewrites `Price[Q1]`). Type discipline holds at the basis: `SUM` over a row-header column is a C9 type error, `COUNT` is fine. Names are load-bearing; still structural, now lighter.
- **The accessibility rhyme, observed thrice** · noted as a law-candidate (2026-07-16) — data/time for values, abbr for names, scope/headers for ranges: whenever this design needs a machine-form/human-form split, HTML already built the seat, because accessibility needed it first. Formulas and screen readers keep wanting the same things. Not yet a stone; if it survives the coming rounds, it graduates.
- **Scaffolding references** · pinned (C16, 2026-07-15) — The adapter's lifecycle in one place: parse coordinate tokens at the boundary, resolve through the grid map, adjust in `appendTransaction` via transaction mapping, upgrade at naming through rename propagation — the same machinery, firing for a better reason. Serialized scaffolding refs are honest markup: they document the table's actual semantic immaturity and heal when maturity arrives. Grammar cargo for the naming round: the lexical rule for names that look like coordinates (a column literally named "A1").
- **This-row contextual references** · open (surfaced by the fill-handle round) — `=Price*Qty` inside a data row meaning "at my row" (the shape of Excel's structured `[@Price]`, bolted on late; native here). Makes fill-down literal copying and is the bridge to `col data-formula`. Needs its grammar rule in §9.
- **Parked glimpses** — `<output for>` as semantic wrapper for computed values; addressing as a citizen of the automation register; `<meter>`/`<progress>` as native-visualization format kinds (machine value, human text, and the rendering, all spec — Excel's data bars as furniture); `<caption>` as the table's own name, the seat waiting for the day formulas cross tables in one document; **subtotals live in tfoot's multiple rows** (formula round, 2026-07-17) — a per-partition summary inside its tbody would sum its own range, and the cycle error is the design *teaching* where summaries belong: one tfoot row per partition plus the grand total, all outside the data, no double counting possible by construction — the answer Excel needed SUBTOTAL's contortions for; awaits the partition round.

### 9 · Formula language

The v1 cut landed (formula round, 2026-07-17) and was built the same day (battleground 2): lexer, recursive-descent parser, the five functions, and the two v1 reference forms are live, suite-pressed, and coordinate-free. Exact spellings still await the christening round. Provisional in the build, awaiting rounds: a standing cell's raw value is its text parsed as a canonical number (the typed-value layer of §3 replaces exactly this seam); `COUNT` counts non-empty cells (its open below stands).

- **The v1 language** · settled as scope (Egildo) — Number literals, `+ - * / ( )` with unary minus, and five functions: `SUM`, `AVG`, `MIN`, `MAX`, `COUNT` — the manual's claim, held. The smallest language that writes every formula in the manual's showcase. No conditionals, no strings, no dates-in-formulas, no volatiles; the function set grows by rounds, never by drift. Open inside the cut: `COUNT`'s exact meaning (counts non-empty? counts numeric?).
- **v1 reference forms** · settled as scope — Bare `Name` (column or row: the grain revelation makes them one machinery) and the intersection `Col[Row]`. Group unions and partition slices fall out of v1 *naturally* — they need spanning headers, which v1 already forbids on the merged-cells side; the cut lands on a seam that was already there. This-row references wait for the col-automation round.
- **Names lex as bare identifiers; spaces demand an `abbr`** · settled (formula round) — No quoting syntax invented: the escape hatch already exists in the spec's own furniture, and the manual's example (`abbr="Prezzo"` for "Prezzo unitario") implied the rule before it was spoken. Grammar cargo from C16 stands: the lexical rule for coordinate-lookalike names.
- **The serialized grammar is canonical and invariant** · settled (formula round) — Dot decimal, comma argument separators, locale-independent: a formula lives in an attribute and must survive crossing documents and locales. Excel's localized formula texts are the famous wound; refused. Display-side localization of formula text, if it ever comes, is presentation and arrives without breaking a document.
- **The full reference grammar, sketched by the spec for later** (C14): `Col[RowGroup]` (partition slice), `GroupName` (union), `Col[R1:R2]` (span slice), qualified names (`2025[Jan]`), the this-row contextual form (§8). Ambiguity rules belong to the naming round. **The kernel grammar contains no coordinate tokens** (C16): the scaffolding adapter extends the grammar at its own boundary, so a strictly-semantic deployment has zero positional ambiguity by construction.

### 10 · Evaluation & validation

How declarations become true, and what happens when they can't. Surveyed 2026-07-15: Excel's recalculation documentation; HyperFormula's dependency graph.

- **The evaluation model** · pinned; first form built (battleground 2, 2026-07-17) — A dependency graph over resolved references with named ranges as first-class nodes (HyperFormula's range-node insight, natural under semantic addressing: a formula depends on the *name*; membership changes dirty the range node while references stay whole). On settle: evaluate within the dispatch, each cell visited exactly once. The built form is the economical reading: memoized descent with a visiting-set for cycle detection, and a *conservative* dirty set — any document change recomputes every formula cell in every table (idempotence stops re-entry; each cell still visited once, so the pin's test holds) — precision dirty-marking from the settled cell arrives when table sizes demand it. Observed and embraced: enforcement rides the *undo* too, recomputing totals for restored data — doctrine over cache, no observable state disagrees with its inputs.
- **Cycles are errors, not iterations** · settled — Detected at settle, produce an error value; no iterative mode. Excel ships one; economy says no.
- **No volatile functions in v1** · settled — Functions are pure over cell values; volatiles are poison under settle-only recompute. Reopening requires a recompute-trigger design first.
- **Evaluation is synchronous and bounded** · settled — It runs in the dispatch path; no async automations in the enforcement path, ever. Async, if it comes, computes outside and dispatches a settle.
- **Errors are values** · settled; first tokens live (battleground 2) — A typed error value occupies the cell and propagates (unknown name, dangling reference, type mismatch, division by zero, cycle). Errors are content — serialization truth extends to failure. Live tokens: `#NAME?`, `#CYCLE!`, `#DIV/0!`, and `#VALUE!` (the text-in-an-aggregate trap we refuse, plus type errors — a token the manual never listed; christening cargo). Provisional wart, recorded: an *unparseable* formula currently settles and evaluates to `#NAME?` — the better design is refusal at the seam (validation with teeth), which waits for its UI round. `#REF?` has no v1 producer (a deleted column is an unknown name here, not a dangling coordinate). **Error markup** · open, promoted to pre-v1 gate (formula round, 2026-07-17) — errors serialize, so `#CYCLE!` needs its P2-worthy costume before v1 ships anything; its own small round.
- **Two species of validation, kept apart** · pinned — Resolution errors (automation failing) versus data validation (content violating declared expectations). Spreadsheets silently skip text inside SUM — a trap we refuse. Glimpse, parked: typed columns as declarations the plugin keeps true (§8).
- **Adopt vs build** · settled by the probe (battleground 2, 2026-07-17) — Built small: lexer, recursive-descent parser, and memoized-descent evaluator total a few hundred lines with zero dependencies and zero coordinate code (C16's purity test passes by construction); HyperFormula's A1-centric machinery had nothing left to sell. The graph *shape* (names as first-class nodes) remains the stolen insight it always was.
- **Battleground 2's build order** · noted (formula round, 2026-07-17) — grid map (§2; arrow up/down wants it anyway) → the standing survey duty (read the spec's header-association algorithm text) → the region-filtered resolver (§8) → name table and dependency graph → evaluator riding `appendTransaction` (C8's second duty). The C16 adapter is part of the *release* story (C11's bottom step) but not this battleground's trench — its own battleground after the kernel.

## The borders

### 11 · Serialization, clipboard, export

- **Emission is pristine** · pinned — Serializing any table satisfies P2 and C3's tests. The stale-value rule (§3) governs cold parsing.
- **Paste is a normalization event** · pinned (survey, 2026-07-15) — Pasted fragments arrive ragged; C8's shape duty repairs them into legal anatomy — harder for us than the incumbent, since "legal" includes regions. Paste into a computed cell stays on the verify list (§3).
- **Clipboard carries semantics** · stub — Copying cells yields a real `<table>` fragment (values in content, formulas in attributes, both survive by C3). Cross-application behavior (Excel, Sheets) unexplored.
- **Parse-time scope normalization** · open (scope round, 2026-07-16) — Wild tables mostly omit `scope`; browsers and AT infer it. Do we write explicit scope during C8's shape repair — making documents more accessible than they arrived (P6 at its most literal), or is that the plugin editing markup nobody asked it to touch? Both instincts have teeth; its own round.
- **Export is not the document** · open (audit finding) — Constructed stylesheets don't serialize: the principle working, not failing. Whether a deliberate export *bundles* presentation as a separate artifact is a distinct question from P3.
